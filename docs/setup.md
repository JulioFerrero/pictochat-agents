# Setup

## What you need

| | Tested with | Also works |
|---|---|---|
| DS | DS Lite | DS, DSi (PictoChat in DS mode) |
| Radio | Waveshare ESP32-S3-LCD-2 (an ESP32-S3 with a 2" screen) | ESP32-C3 boards. A classic ESP32 builds but is untested on air |
| Computer | macOS on Apple Silicon | Linux should work |
| AI | [Claude Code](https://claude.com/claude-code), logged in | a Claude subscription or an API key |

Plug the radio in through the chip's own USB port: on boards with two ports, the one marked USB.

## Install

```sh
git clone https://github.com/JulioFerrero/pictochat-agents.git && cd pictochat-agents
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
```

## Flash the radio

You need [ESP-IDF 5.4](https://docs.espressif.com/projects/esp-idf/en/v5.4.1/esp32s3/get-started/index.html) in
`~/esp/esp-idf-v5.4.1`, or `IDF_PATH` set. The script finds the board, works out the chip, then builds and flashes:

```sh
tools/flash_modem.sh            # or: tools/flash_modem.sh /dev/cu.usbmodem1101
```

## Settings

`pictoagents.json`, next to `run.py`. It isn't committed, and every key is optional:

```json
{
  "serial": "auto",
  "trust": ["00:09:bf:12:34:56"],
  "screen": "waveshare-s3-lcd2",
  "name": "Claude",
  "color": 4,
  "members": true
}
```

| Key | What it does |
|---|---|
| `serial` | the radio's port; `auto` takes the first `/dev/cu.usbmodem*` |
| `trust` | hardware (MAC) addresses of the DSes that may make agents use the computer. To find yours: start without it, enter the room, run `./pictoagents status` |
| `screen` | draws the status screen on the radio board; leave it out on a board without one |
| `name`, `color` | the main agent's nickname and colour (DS favourite colour 0-15) |
| `members` | `true` (the default): agents join the room as people of their own. `false`: every reply comes from the host, starting with the agent's name |
| `attribution` | what agents write on their commits and pull requests, see below |

## Commands

```sh
./pictoagents start            # radio host, agents and status screen, in the background
./pictoagents status [--json]  # radio signal, who is in the room, each agent and what it is doing
./pictoagents logs [host|manager|run] [-n 40]
./pictoagents say hola         # write into the room
./pictoagents agents           # the agents, their folders and the trusted DSes
./pictoagents stop             # or: restart
```

`start` runs an ordinary background process (`run.py`) that restarts the host and the agents when they stop, for
example when the radio is unplugged. It keeps running until `stop`, logout or a reboot; nothing is installed to run at
login. `status --json` is for other programs, such as another Claude session or a small UI.

## Commits and pull requests

Agents that work on the computer sign what they make, with Claude Code's `attribution` setting:

> 🎮 Generated by Coder with PictoChat x [Claude Code](https://claude.com/claude-code), from a Nintendo DS

To change the wording, put it in `pictoagents.json`; `{agent}` is the agent's name:

```json
"attribution": {"commit": "Generated by {agent} from a DS\n\nCo-Authored-By: Claude <noreply@anthropic.com>",
                "pr": "Generated by {agent} from a DS"}
```

## Testing without a DS

`tools/fake_room.py` stands in for the host: it replays a DS joining, sends pictures with text on them (or captures
from `captures/`) and saves the agents' replies as PNGs. `PICTO_STATE_DIR` and `PICTO_PC_HOME` keep test agents away
from the real ones:

```sh
export PICTO_STATE_DIR=/tmp/picto-test PICTO_PC_HOME=/tmp/picto-test/pc FAKE_OUT=/tmp/picto-test
.venv/bin/python tools/fake_room.py 7799 Ana 'hola!' '/new Coder pc writes code' '@coder create notes.txt' &
.venv/bin/python agents/manager.py --port 7799 --trust 00:09:bf:12:34:56
```

`display/room_display.py --preview room.png` draws the room screen without hardware, and `pictochat.py selftest`
checks the PictoChat frame builders.
